# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Next.js 15 (App Router) + React 19 + TypeScript + Tailwind v4 + Framer Motion + lucide-react. `output: "standalone"` for the production Docker image.

## Commands

```bash
npm install                 # install deps
npm run dev                 # dev server (default port 3000)
npm run build               # production build (verifies TS + Tailwind)
npm run start               # serve production build
npm run lint                # eslint
npm run typecheck           # tsc --noEmit
npm test                    # vitest: tests/ (lógica de servidor: actions, feeds, dates, telegram, rate limit, JSON-LD)
```

CI runs all four plus `npm audit --omit=dev --audit-level=critical` and the build (the level is `critical` because Next 15.5 nests a build-time-only postcss with a `high` advisory that only Next 16 fixes; lower it to `high` after that migration). Node **22** in both the Dockerfile and `ci.yml` (Node 20 is out of support since April 2026); keep them in sync.

If `npm run dev` (and `npx next ...`) returns a truncated "Errors: 1 | Warnings: 0" summary, the npx wrapper is swallowing output — call the binary directly: `./node_modules/.bin/next dev`.

## Architecture

Single long-scroll landing page modeled after the **DJSwarthy Academy** reference site (`https://fictional-octo-guacamole-rose.vercel.app/`). The visual identity (palette, typography, gradient, glow, structure) is copied from that reference; the content is rewritten as an **artist presentation site** (booking, sets, fechas) instead of a course landing.

- `app/page.tsx` — async server component that fetches the YouTube + SoundCloud feeds (`lib/feeds.ts`) and the Spotify discography (`lib/spotify.ts`) with `Promise.allSettled` (a fetcher that throws degrades to `[]`/`null` instead of taking the home down) and composes the sections in order: Hero → Stats → About → Dates → Mixes → Releases → Formats → Venues → Testimonials → Socials → Faq → Contact → FinalCta. `export const revalidate = 3600` pins the home as static + hourly ISR; **never add `cache: "no-store"` to a fetch reached from this page** (it turns the route dynamic, which is what the Spotify token POST used to do). Reorder by editing this file alone; sections do not depend on each other (FinalCta embeds BookingForm). `Dates` and `Testimonials` render nothing while `site.dates` / `site.testimonials` are empty.
- **Animation architecture.** `components/motion/MotionProvider.tsx` wraps the app in `LazyMotion` (features loaded from `components/motion/features.ts` in a separate chunk, `strict` mode) + `MotionConfig reducedMotion="user"`. Use `m` from framer-motion, **never `motion`** (strict mode throws). Purely presentational sections (Hero, Stats, About, Dates, Mixes, Releases, Formats, Venues, Testimonials, Socials, FinalCta) are **server components** that wrap animated nodes in `components/motion/Reveal.tsx`; only Faq, Contact, BookingForm, Navbar, StickyCta, MediaFacade and SpotifyProfilePlayer are client components. This keeps `lib/data.ts` out of the client bundle (home route went from 53 kB to 18.5 kB, First Load JS 164 → 130 kB). The Hero animates with the CSS class `fade-up` instead of Framer so the above-the-fold copy paints without JavaScript.
- `components/Overline.tsx`, `components/SectionHeading.tsx`, `components/NewTabHint.tsx` — shared section header pieces (the decorative ★ is `aria-hidden`) and the screen-reader-only "(se abre en una pestaña nueva)" hint every `target="_blank"` link must carry.
- `components/forms/primitives.tsx` — shared form pieces (`inputClass`, `Honeypot`, `FormError` with `role="alert"`, `FormSuccess` which takes focus on mount, `SubmitButton` with `aria-disabled`, `field()` to read FormData as string). Both forms wrap the server action call in try/catch so a thrown action still shows an error. BookingForm sets the date `min` in an effect (computing it during render caused a hydration mismatch).
- `lib/site.ts` — `SITE_URL`, `SITE_NAME`, `OG_IMAGE` and `CONTENT_UPDATED_AT` (feeds the sitemap `lastModified`; bump it by hand when copy changes). Import from here, not from `lib/json-ld.ts`, when you only need the URL.
- `app/opengraph-image.tsx` — generates the 1200×630 social image at build time with `next/og` (dark background, "DJ SWARTHY", slogan, portrait from `public/images/og.jpg`). The brand font is vendored in `assets/fonts/BebasNeue-Regular.ttf` (OFL) because `next/font` is not available inside `ImageResponse`. Do not declare `openGraph.images` in `layout.tsx`: the file convention wins.
- `app/not-found.tsx`, `app/error.tsx`, `app/manifest.ts` — branded 404, client error boundary and web manifest. Icons (`public/apple-touch-icon.png`, `icon-192/512.png`, `icon-512-maskable.png`) are the isotype inverted onto `#0a0a0a`, generated once with sharp.
- `app/privacidad/page.tsx` — GDPR privacy policy. It is the legal basis for the two forms, both of which require an explicit consent checkbox (`components/ConsentCheckbox.tsx`) that the server actions re-validate.
- `app/press-kit/page.tsx` — EPK: short/long bio, quick facts, technical rider and downloadable artwork, all driven by `site.press`.
- `lib/dates.ts` — `upcomingDates(now?)` drops past gigs and sorts ascending, comparing ISO day strings in **Europe/Madrid** (`todayIso()`), so the container's UTC clock never shifts a gig by a day. Also exports `isIsoDay()` (used by the booking action to validate the event date). Shared by `app/page.tsx` and `lib/json-ld.ts` so the agenda and the `MusicEvent` schema never disagree. `Dates.tsx` formats with an explicit `timeZone` for the same reason.
- `app/layout.tsx` — loads two Google fonts (`Bebas Neue` → display, `Inter` → body) and exposes them as `--font-bebas` and `--font-inter`. Also carries the SEO surface: metadata + OpenGraph/Twitter text (the image comes from `app/opengraph-image.tsx`), JSON-LD and the Plausible analytics script (`data-domain="djswarthy.es"`). The only `preconnect` is Plausible: the players are facades and thumbnails go through `/_next/image`, so preconnecting to YouTube/SoundCloud was wasted work.
- `lib/json-ld.ts` — `buildJsonLdString(now?)` builds the graph (`MusicGroup`, `WebSite`, `Service`, `FAQPage` from `site.faq`, one `MusicEvent` per upcoming gig) **per render** (a module-level constant froze the event list at process start) and escapes `<` so no copy can close the `<script>` tag.
- `app/actions/booking.ts` / `app/actions/contact.ts` — server actions that forward form submissions to a Telegram chat via `lib/telegram.ts` (needs `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` env vars). They are public endpoints, so every field goes through `cleanField`/`cleanLine` (non-strings become `""`, single-line fields lose newlines so nobody can forge a "Responder a:" line), consent must be `=== true`, the booking date must be a real ISO day ≥ today in Madrid, and honeypot (`web`) submissions are silently accepted. `sendTelegramMessage` has a 10 s timeout, logs only the HTTP status (never the body or the URL, which carries the token) and truncates with `truncateHtml` so a cut never splits an entity or leaves `<b>` open. `lib/rate-limit.ts` trusts **only** `X-Real-IP` (nginx sets it); `X-Forwarded-For` is ignored on purpose.
- `lib/feeds.ts` — regex-parses the public YouTube and SoundCloud feeds (no API keys). Every fetch has an 8 s `AbortSignal.timeout`, bodies are capped, ids are validated against the platform's format before they reach an iframe `src`, and each feed returns at most `FEED_LIMIT` (8) items so the RSC payload does not carry 30 unused videos. Sends a browser User-Agent because YouTube 429s datacenter IPs otherwise. **YouTube retired its public RSS feeds** (`/feeds/videos.xml` now 404s for every channel), so `getLatestYouTubeVideos()` tries RSS first — it self-heals if YouTube brings it back — and otherwise falls back to scraping the `ytInitialData` JSON out of `youtube.com/@swarthy_dj/videos`. That path has no exact publish date, only YouTube's relative age ("hace 9 días"), which travels as `VideoItem.publishedLabel` and is what `Mixes` renders when `publishedAt` is empty. Returns `[]` on any failure; `Mixes` falls back to plain channel links. `Mixes` splits the feeds with `lib/mixes.ts`: `isSet()` decides by title ("mix", "set", "session", "62 Min"…, but not "Original/Extended mix" or "Remix") whether an item is a DJ set or a production. The two featured cards are always sets (newest of each platform, or two of one if the other has none) because the hero CTA promises "último set"; the remaining sets and the productions/covers get separate grids of up to 6. Every player is a **facade**: the thumbnail is a button and the `<iframe>` is only mounted on click, so YouTube/SoundCloud third-party cookies are never set on a plain visit. YouTube serves thumbnails from `i.ytimg.com` *and* `i1/i2/i3/i4.ytimg.com`, hence the `*.ytimg.com` `remotePattern` in `next.config.ts`.
- `lib/spotify.ts` — public artist data for `site.spotifyArtistId`. Two paths: the official Web API via **Client Credentials** (`SPOTIFY_CLIENT_ID` + `SPOTIFY_CLIENT_SECRET`) to list albums and singles with artwork, and the credential-free **public oEmbed** for the artist's name and photo. Without credentials it returns `[]` and `Releases` falls back to the profile player, which already lists the top tracks. The token is cached in module memory because a POST `fetch` never enters Next's Data Cache.
- `components/MediaFacade.tsx` — the facade shared by `Mixes` and `Releases`: a clickable cover (16:9 or 1:1) that only mounts the `<iframe>` after the click (and moves focus to it), so YouTube/SoundCloud/Spotify never set third-party cookies on a plain visit. Any new player must go through it. Only one facade can be playing: `components/ActivePlayer.tsx` (provider in `app/layout.tsx`) keeps the active id, and clicking another facade unmounts the previous iframe so two mixes never sound at once. `components/SpotifyEmbed.tsx` is the plain iframe; `components/SpotifyProfilePlayer.tsx` is the client fallback card.
- `components/sections/Releases.tsx` — the `#spotify` section: a grid of releases with a per-album embed, or the artist profile player as fallback.
- `app/sitemap.ts`, `app/robots.ts`, `app/api/health/route.ts` — sitemap (home + press kit, `lastModified` from `CONTENT_UPDATED_AT`; `/privacidad` is `noindex` and left out), robots (disallows `/api/`), and the healthcheck endpoint used by docker-compose.
- `docs/AUDIT_PROMPT.md` — reusable prompt to run a multi-agent audit (security, a11y, SEO, React/perf, infra) and apply the findings on a branch.
- `docs/DESIGN_PROMPT.md` — reusable prompt for a design/product review from the point of view of a web designer for professional DJs (promoter booking funnel, music experience, EPK, copy, benchmark against other DJ sites), within the locked visual direction. Produces a report; changes only after the user picks them.
- `app/globals.css` — Tailwind v4 `@theme` block declares the design tokens. Renaming a token here renames the utility class everywhere. Custom utilities defined in `@layer utilities` are the brand primitives:
  - `gradient-primary` — the rojo→naranja diagonal gradient (`#e11d48 → #f97316`) used on CTAs, badges, step circles, value-stack footer.
  - `text-gradient` — same gradient applied to text via `background-clip: text`. Used on every section heading's accent word.
  - `gradient-glow` / `gradient-glow-orange` — the radial red/orange halo used as ambient background glow behind hero, contact and final CTA.
  - `shadow-glow` / `shadow-glow-strong` — the colored drop-shadow under primary buttons and featured cards.
  - `pulse-dot` — the keyframe used by "live" badge dots.
  - `card-lift` — uniform hover-lift for cards (venues, socials).
- `lib/data.ts` — single source of truth for the static content (hero copy, bio, formats with includes lists, venues, FAQ, socials). Sections import from here; replacing copy never touches component files.
- `components/sections/*` — one file per section, all client components animated with Framer Motion. `BookingForm` (inside FinalCta, anchor `#booking`) and `Contact` (anchor `#contacto`) submit to the Telegram server actions.
- `components/Navbar.tsx`, `components/Footer.tsx`, `components/StickyCta.tsx` — chrome. All anchors are **absolute** (`/#about`), because the navbar is also rendered on `/press-kit` and `/privacidad`. The mobile menu closes on Escape, caps its height, and the hidden StickyCta uses `invisible` so it leaves the tab order; it also hides (IntersectionObserver) while `#booking`, `#contacto` or the footer are on screen so it never covers the submit button. Form inputs are `text-base` below `md` because iOS Safari zooms into any field under 16 px.
- `public/images/` — venue photos + portrait; `public/logo-isotype.png` and `public/logo-wordmark.png` are the artist's logos. The isotype is rendered with `className="invert"` (black silhouette → white). `og.jpg` is the compressed OpenGraph image.

**Do not drift back to "club neon" or "editorial cinematic" aesthetics** — both were tried and rejected. The locked direction is the reference URL above. Known, accepted trade-offs of that design: white text on the red→orange gradient buttons sits below 4.5:1 on the orange end, and the hero equalizer/pulse animations are infinite (they respect `prefers-reduced-motion`). Changing either is a design decision, not a bug fix.

## Deployment

Target server: `ssh ubuntu@143.47.52.87` (aarch64/ARM, existing nginx + certbot + n8n stack). The deploy user is `ubuntu`, already in the `docker` group — no `sudo` needed, and nothing runs as `root`. **nginx runs on the host, not in Docker** — the compose publishes the container only on the loopback (`127.0.0.1:3001 -> 3000`) and nginx `proxy_pass`es to it. The image is built and stored on that same server; there is no registry.

- `Dockerfile` — multi-stage (deps → builder → runner). `node:20-alpine`, runs as non-root, executes `node server.js` from the `standalone` output.
- `docker-compose.yml` — single `web` service, no custom networks: it publishes `127.0.0.1:3001 -> 3000` so the host's nginx can reach it over the loopback. Hardened: `init: true`, `cap_drop: ALL`, `no-new-privileges`, pids/memory limits and capped json-file logs. Healthcheck against `localhost:3000` inside the container.
- `deploy/nginx-djswarthy.conf` — sample vhost: HTTP→HTTPS redirect, www → apex canonicalization, keepalive upstream, `limit_req` for the form POSTs, `proxy_pass` to the published loopback port. **Security headers live only in `next.config.ts`** (HSTS, CSP, COOP, Referrer-Policy…); nginx must not re-add them with other values.
- `deploy/README.md` — first-deploy and update walkthrough, plus the GitHub secrets the pipeline needs.
- `.github/workflows/ci.yml` — lint + typecheck + tests + `npm audit` + `next build` on every PR and non-main push. Also exposed as `workflow_call`. Both workflows run with `permissions: contents: read`.
- `.github/workflows/deploy.yml` — on push to `main`: runs CI, then SSHes into the server, `git reset --hard` to the pushed SHA, `docker compose build && up -d`, polls `/api/health`, and **rolls back to the previous commit** if the healthcheck never goes green. Deploy values travel to the remote script as positional arguments (`bash -s --`), never interpolated into the command string.

`djswarthy.es` (canonical) and `www.djswarthy.es` (redirects to apex). Both A-records must point to `143.47.52.87` before certbot can issue the cert.

## Not yet wired

- Forms require `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` in the container environment; without them submissions fail with a generic error.
- `site.whatsapp` is empty, so the WhatsApp CTA in `FinalCta` does not render. Fill it with an international number, digits only (e.g. `34600123456`).
- `site.dates` and `site.testimonials` are empty; their sections stay hidden until real gigs/quotes are added. **Never fill them with placeholder content, not even "for a preview"** — testimonials are social proof and fake dates are emitted as `MusicEvent` schema at real venues (a demo set shipped to production once and had to be removed).
- Keeper has no venue photo (`Venue.img` is optional and it falls back to a typographic card). The previous image was a scanned VIP consumption card: it clashed with the rest of the grid **and carried a third party's printed name**, so it was deleted from `public/` rather than left unreferenced. Any replacement must be an actual venue photo with no personal data in frame.
- The press kit lists downloadable images but no rider PDF; `site.press.rider` renders the same content as HTML instead.
- `SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET` are optional (see `.env.example`): without them the Spotify section degrades to the artist profile player instead of the album grid. Adding a new embed host means widening `frame-src` in the CSP **and** `images.remotePatterns` in `next.config.ts`.
